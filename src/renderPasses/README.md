# RenderPasses Module Terminology

This module uses the same fixed terms as renderer:

- Node: top-level feature unit.
- pass: executable unit emitted by a Node.
- submitNode: debug-named graph control marker (not a business Node).

Rules:

- A Node may emit multiple passes.
- The `rtobject` pipeline orders one graphics `AccelerationStructureBuild -> LightPrepare -> PathTracing -> Ui` batch -> `rtobject.GraphicsToCompute` submit -> a pre-acquire compute `selected post-processing -> Present.Convert` batch (plus optional screenshot/readback copies) -> `Present.AcquireSwapchainImage` -> the final compute `Present.CopyToSwapchain` batch. The post-processing slot contains exactly one Accumulate or DLSS Ray Reconstruction node, with RR selected by default. AS build-to-trace visibility is enforced by the RDG's precise in-batch acceleration-structure barrier, while adjacent batches share the renderer's monotonically increasing timeline semaphore and wait at the union of the actual consumer stages.
- EmbeddedTriangle Node targets graphics queue output, binds renderer global frame uniforms, and emits a single draw-call demo pass.
- AccelerationStructureBuild Node targets graphics or compute queue AS build work, owns renderer-side BLAS/TLAS cache resources plus RT material sideband frame buffers, allocates BLAS storage from one node-owned atlas buffer, batches dirty rebuild-only BLAS builds, rebuilds TLAS from scene TLAS packets, and publishes `frameResource::sceneTlas` with dense instance/geometry/material metadata plus scene vertex/index atlas resources for RT shaders.
- LightPrepare Node targets CPU-to-GPU frame upload work, prepends the warm default directional sun light, consumes active scene light packets, writes the set 6 scene light header/list/alias-table buffers into per-frame CPU-visible GPU buffers, and publishes `frameResource::sceneLightHeader`, `frameResource::sceneLights`, plus `frameResource::sceneLightAliasTable`.
- PathTracing Node targets ray tracing work, consumes `frameResource::sceneTlas`, the RT material sideband buffers, scene vertex/index atlas resources, published scene light buffers, and `frameData::sceneRtHitSbtPlan`, and writes a fixed 1spp noisy result plus the six non-color RR guides at `NodeFrameParameters::resolutionPlan.renderExtent`. The seven images are color `RGBA16F`, hardware depth `R32F`, diffuse albedo `RGBA16F`, specular albedo `RGBA16F`, world-space normal with linear roughness in alpha `RGBA16F`, jitter-decoupled previous-pixel-minus-current-pixel motion `RG16F`, and world-space specular hit distance `R16F`. Every image has one renderer-persistent slot per frame in flight with retained layout/access/ownership state and independent allocation extent/format metadata. Guide allocation is lazy during build and grows or reformats only the current frame slot after `Device::beginFrame()` has waited for that slot; other in-flight slots remain untouched. RDG declarations and ray dispatch use the current logical render extent even when the selected backing image is larger. The current `rtobject` schedule transfers them from the graphics PathTracing batch to the selected compute post-processing node. The node publishes the color as `frameResource::presentSourceColor` and all seven images as their explicit `dlss.rr.input.*` keys. It owns its link-time root variant key, staged UI draft, Slang assignment generation for `kMaxSurfaceBounces` and `RussianRoulettePolicy`, a node-local RT pipeline cache keyed by root variant plus hit-group permutation set, and a separate SBT cache keyed by pipeline key plus hit record plan. Pipeline misses synchronously compile only the Slang variants required by the active scene and create the RT PSO on the graph build thread; SBT misses rebuild only the shader-binding table for the active record plan. Its shader is split into a thin fixed `shader/renderer/pathTracing.slang` entry module plus focused `shader/renderer/pathTracing/*` modules: the entry constructs a `Scheduler`, the scheduler runs exactly one raygen path per pixel, `Pt` owns the per-path `PathState` plus trace/hit/miss/output methods, closest-hit builds a `ClosestHitInput` and delegates material payload resolution plus BSDF scatter sampling through the link-time `CHS : ICHS` contract in `shader/include/pathTracing/chs.slang`, and the raygen core performs pixel- and monotonic-sample-frame-based RNG seeding, direct lighting from glTF photometric scene lights, finite-distance shadow rays for punctual lights, emissive contribution, roulette, next-bounce state updates, and guide capture. The node splits hit selection into BSDF variant keys and alpha-policy hit-group keys: alpha-mask hit groups attach `ahAlphaMask` but can reuse the same closest-hit CHS stage as opaque hit groups with the same BSDF key, while SBT records remain per geometry.
- PathTracing resolves its scene dependencies as one private typed input bundle. Missing TLAS, incomplete RT sideband, and invalid SBT plan states share reason-labeled clears across the complete seven-image set. Its named RHI RT program assembly creates the stage/group mapping once; SBT sections and records query the resulting pipeline group names rather than assuming numeric group positions. It does not generate the optional experimental ray-direction, 3D-motion-vector, high-resolution-depth, disocclusion, or responsivity guides.
- Accumulate Node is the selectable non-RR `rtobject` post-processing mode. It independently snapshots the unjittered render-camera view/projection matrices, owns its sample count, and invalidates only its own history when that transform changes or its retained history images are recreated.
- DlssRayReconstruction Node defaults to disabled as a reusable node, consumes only explicit `dlss.rr.input.*` frame keys, preserves the complete bundled DLSS 310.7.0 RR create/evaluate contract for programmatic configuration, evaluates through `nr.rhi:dlss`, and normally publishes `dlss.rr.output.color` plus optional `dlss.rr.output.alpha`. Its single staged developer UI session exposes Enable, Quality, one preset for each of the five quality modes, a DLAA-only output bypass, Preset E/Depth of Field guidance, motion-vector visualization with its conditional legend, one-shot history reset, runtime status, and queried optimal settings. All other create/evaluate settings, create flags, optional-resource inclusion, and subrect controls remain available only through `DlssRayReconstructionNodeInput`. Bypass remains editable only in DLAA; changing to another quality clears it before staging, and programmatic non-DLAA bypass fails fast. Bypass still runs NGX evaluation and preserves RR history, but publishes the PathTracing input color to the configured output key instead of the RR output. The optional debug view runs after NGX so RR history continues normally, then replaces only the presented RR color with a Messiah-style logarithmically amplified visualization of the exact pixel-space MV input: neutral motion is `(R,G)=(0.5,0.5)`, R encodes X, G encodes Y, and invalid values are magenta. The default `rtobject` RR graph owns a bounded five-quality resolution controller: before scene extraction and node build, its generic renderer resolver reads the node's effective staged Enable/Quality/Bypass request, queries or reuses exact NGX optimal settings for the current display extent, and publishes display/render extents plus a transition reset. PathTracing produces at that render extent; coordinated RR forbids node-local size overrides, validates the same controller snapshot, targets the display extent, and reuses the snapshot without a second optimal-settings query. Disabling RR returns the identity plan so low-resolution PathTracing output cannot bypass reconstruction into Present. Standalone RR nodes without the controller retain their existing programmatic overrides and late optimal-settings query. Both paths validate query success, non-zero optimal/min/max dimensions, ordered target-bounded ranges, and DLAA target equality before feature creation. Automatic RR matrices come from `NodeFrameParameters::renderCameraConstants`, which is the actual selected scene or override camera before projection jitter; jitter is supplied separately and scaled by render extent. RR evaluation reset combines resolution transitions, renderer camera reset, node-local one-shot reset, and feature-lifecycle reset. NGX is isolated in the project-owned MSVC Release bridge; MSVC and clang++/libc++ hosts use the same validated C ABI and Release feature DLL.
- NormalBuffer Node targets graphics queue output, outputs world-space normals for any scene, binds the scene geometry atlas once per parallel record chunk, samples normal maps through the renderer global `gSceneTextures[]` bindless table when a draw provides a non-zero normal texture ID, and uses `RasterPassBuilder::recordParallel(...)` to record independent contiguous ranges of scene raster draws.
- Ui Node targets graphics queue UI composition, renders app sections plus renderer-collected node UI sections, uploads GPU-only texture pixels through the RHI upload ring before graph import, keeps overlay texture reads in the render graph resource-intent path, and uses its local texture-table revision only as the content mutation source for the renderer-owned bindless table cache. UI texture images attach retained image states after upload synchronization so later RDG imports update their final sampled layout/access through the common tracking path.
- Present Node targets the compute queue final output path. It consumes `frameResource::presentSourceColor`, optionally composites `frameResource::uiColor` when a UI node published one, converts to the selected SDR/HDR swapchain output encoding into a retained imported converted-color image, and copies a swapchain-ready image. When a `PresentReadbackTarget` is provided, it inserts `Present.CopyToReadback` after compute conversion. After all optional screenshot/readback work, `Present.AcquireSwapchainImage` splits the pre-acquire work from `Present.CopyToSwapchain`; only the final transfer copy batch binds the acquired swapchain image and waits on image-available at `eTransfer`. Present copy/readback/screenshot passes use renderer transfer ops so image aspects, readback barriers, and present destination use declarations stay centralized. Its UI panel stages next-frame opacity changes and screenshot requests; screenshots copy the pre-present linear source image directly into a node-owned readback buffer and save an EXR after the captured frame slot's fence has completed.

## Binding Checklist

Shader-visible bindings in this module must be reflection-led through renderer-side pass builders. Nodes should use `PipelineRuntime`, `NodeBuildContext::globalResources`, `RasterPassBuilder`, `ComputePassBuilder`, and `RayTracingPassBuilder` for persistent pipeline descriptor sets, renderer-owned global frame resources, static descriptor writes, push constants, dynamic descriptor snapshots, acceleration-structure descriptors, pass shader-stage scopes, and the split prepare/record deployment path. Raster passes should use explicit resource stage intent for known vertex-only or fragment-only descriptor access.

- Allowed direct command recording inside builder record callbacks: vertex/index buffers, draw/dispatch/trace, scissor overrides, per-draw dynamic state, barriers, and copy helpers.
- Direct `context.addPass(...)` remains appropriate for non-shader-visible AS-build/upload passes that do not update or bind shader descriptors. Built-in transfer clears and copies should prefer `nr::renderer::ops`; CPU uploads into GPU-only resources should use the RHI upload ring instead of node-local staging passes.
- Renderer-persistent imported images that can be reused across frames must attach `nr::renderer::RetainedImageState` through the imported-image descriptor or a retained import helper. PathTracing's seven RR inputs retain one image set per frame in flight even though the current diagnostic schedule produces and consumes each set on graphics, preserving frame-slot lifetime isolation. Frame-local imported images, such as `NormalBuffer.Color` / `NormalBuffer.Depth`, `Ui.Buffer`, and per-frame UI buffers, can continue to start from `Undefined` because frame-slot fences prevent overlap. Graph-transient images, such as the DLSS RR output and embedded triangle output, do not need retained state because RDG owns their lifetime for the frame. Scene bindless textures that are not graph-imported images remain governed by the existing upload/retirement lifetime rules; this contract does not extend retained tracking to buffers or acceleration structures.
- Per-node/pass/draw scalar payloads must use push constants only when they are no larger than `nr::rhi::kMaxPushConstantBytes` (128 bytes). Larger payloads must be split into renderer global frame uniforms or buffer/texture upload resources.
- Dynamic or bindless resources may provide a builder `dynamicBindingSnapshot(...)` callback using reflection cursors, but descriptor writes and command-buffer descriptor binding still stay inside the builder prepare/record path. Per-frame bindless descriptor table application caches are renderer-owned; render-pass nodes should not keep node-local applied-version caches.
- Scene bridge data that is consumed during deferred prepare/record work should be captured as `GraphFrameDataHandle` values from `NodeFrameParameters` and resolved through the pass context. Do not capture borrowed `SceneBridgeFrame` references or copy per-node bridge snapshots into record lambdas.
- Optional command-style node UI belongs in `NodeRuntime::collectUi(...)`. UI callbacks should only mutate node-owned staged state. Compile-affecting link-time settings stay node-owned and are translated to `SlangProgramVariantDesc` only by the node that owns the PSO cache. `UiNode` displays collected sections but does not own their state.
- Scene/model raster passes that emit conventional clip-space Y-up positions should select `RasterViewportYMode::ClipSpaceYUp`; screen-space UI passes should keep the default framebuffer-top-left viewport mode.
- A pass that opts into `recordParallel(...)` must treat chunk replay order as semantically unordered. If a feature needs ordered draw groups, split it into multiple ordered passes and declare resource uses at those pass boundaries; use `nr::renderer::use::orderedAfterPrevious(...)` when the next pass needs an explicit barrier despite unchanged queue/layout.
- `NormalBuffer.Raster` consumes `SceneBridgeFrame::geometryBuffers` as the scene vertex/index atlas binding source. Each parallel chunk binds the atlas vertex buffer once, binds the atlas index buffer once when the frame has indexed geometry, and the per-draw loop changes only dynamic raster state, push constants, and atlas-adjusted draw parameters.
- Scene material texture IDs in raster push constants default to 0 and are packed as two 16-bit IDs per 32-bit lane. RT material texture references use the same descriptor IDs. Shader code should use `shader/include/share/materialTextureIds.slang` for the `MaterialTextureSlot` enum, and `shader/include/materialTextureIds.slang` for unpacking helpers. Scene-texture-consuming PSOs install a linear immutable sampler for `gSceneTextures[]` before pipeline creation; renderer global resources bind `gSceneTextures[0]` to a 1x1 neutral white fallback (linear RGBA(1,1,1,1)) and bind resident scene texture image views at `TextureHandle.slot + 1` through a single set 1 / binding 0 variable descriptor array. Missing/unauthored RT material texture slots resolve to ID 0, so the neutral white default multiplies through factor-only material terms without a texture-presence branch. Before graph build, renderer collects table entries from both raster bridge materials and TLAS/RT material references, so PathTracing can sample materials that are only visible through the AS path. Passes that use or may use this table should call `nr.renderPasses:sceneTextureTableBinding`, which is a thin adapter into `RendererCacheSuite::bindlessImageTableCache`; descriptor-set allocation invalidation, fallback prefill, version checks, resident-slot updates, and removed-slot fallback rewrites are renderer-owned.
- `AccelerationStructureBuildNode` consumes build-time scene TLAS packets and scene AS mesh queries only during node build. It keeps BLAS storage in a node-owned atlas buffer, repacks/rebuilds on atlas growth instead of copying opaque AS storage, and validates TLAS hit SBT bucket offsets against the configured hit record count. Its deferred record callbacks resolve node-private graph frame data and call `nr.rhi` AS helpers; they must not capture borrowed scene references.
- `AccelerationStructureBuildNode` also compiles the frame's RT-only multilayer material table from resident scene materials during node build. It writes instance metadata, geometry-to-material and primitive-address records, material headers, ordered layer records, and material texture references into imported storage buffers, then publishes the scene geometry atlas buffers so RT shader-visible nodes can bind all of them through `RayTracingPassBuilder`.
- `LightPrepareNode` keeps one CPU-visible header buffer, one CPU-visible record buffer, and one CPU-visible alias-table buffer per frame slot. Alias weights are Rec.709 luminance times glTF photometric intensity. It inserts a default warm directional sun before scene-authored lights, so normal PathTracing frames have at least one positive-energy alias-table entry; the lower-level alias builder still supports zero-count dummy tables for direct helper use.
- Not allowed in nodes: hand-written descriptor-set update/bind flows, direct `ShaderBindingPool::update(...)` or `resolveDescriptorWriteRequests(...)` usage, direct `CursorPipelineLayout::bindDescriptorSets(...)` for shader-visible bindings, direct `updateResourcesForBindingSnapshot(...)`, direct `bindPreparedResourcesToCommandBuffer(...)`, or direct `pushConstantsToCommandBuffer(...)`.

Current audit note: all built-in project-shader passes use `RasterPassBuilder`, `ComputePassBuilder`, or `RayTracingPassBuilder`. `NormalBuffer.Raster` is the built-in unordered parallel raster pass. Built-in transfer clears/copies, including PathTracing fallback clears and Present readback/screenshot/swapchain copies, use `nr::renderer::ops`. `AccelerationStructureBuildNode` and `LightPrepare.Upload` use direct `context.addPass(...)` because they are AS-build/upload graph passes without shader-visible bindings; `DlssRayReconstructionNode` uses it to record the typed external NGX evaluation after declaring every image use to RDG.
