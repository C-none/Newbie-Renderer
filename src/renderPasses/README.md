# RenderPasses Module Terminology

This module uses the same fixed terms as renderer:

- Node: top-level feature unit.
- pass: executable unit emitted by a Node.
- submitNode: debug-named graph control marker (not a business Node).

Rules:

- A Node may emit multiple passes.
- The `rtobject` pipeline orders one graphics `AccelerationStructureBuild -> LightPrepare -> PathTracing -> Ui` batch -> `rtobject.GraphicsToCompute` submit -> a pre-acquire compute `selected post-processing -> Present.Convert` batch (plus optional screenshot/readback copies) -> `Present.AcquireSwapchainImage` -> the final compute `Present.CopyToSwapchain` batch. The post-processing slot contains exactly one Accumulate or DLSS Ray Reconstruction node, with RR selected by default. AS build-to-trace visibility is enforced by the RDG's precise in-batch acceleration-structure barrier, while adjacent batches share the renderer's monotonically increasing timeline semaphore and wait at the union of the actual consumer stages.
- EmbeddedTriangle Node targets graphics queue output, binds renderer global frame uniforms, and emits a single draw-call demo pass.
- AccelerationStructureBuild Node targets graphics or compute queue AS build work, owns renderer-side BLAS/TLAS cache resources plus RT material sideband frame buffers, and keys an immutable structural plan by scene revisions, ordered packet identity, and one semantic entry per unique mesh. It allocates BLAS storage from one node-owned atlas buffer, batches dirty rebuild-only BLAS builds, writes dynamic instance transforms/masks and rebuilds TLAS every frame, uploads static sideband data once per frame slot and structural-plan generation, and publishes `frameResource::sceneTlas` with dense instance/geometry/material metadata plus scene vertex/index atlas resources for RT shaders.
- LightPrepare Node targets CPU-to-GPU frame upload work, prepends the warm default directional sun light, consumes active scene light packets, writes the set 6 scene light header/list/alias-table buffers into per-frame CPU-visible GPU buffers, and publishes `frameResource::sceneLightHeader`, `frameResource::sceneLights`, plus `frameResource::sceneLightAliasTable`.
- PathTracing Node targets ray tracing work, consumes `frameResource::sceneTlas`, the RT material sideband buffers, scene vertex/index atlas resources, published scene light buffers, and a frame-owned `shared_ptr<const SceneRtHitSbtPlan>` from `frameData::sceneRtHitSbtPlan`, and writes a fixed 1spp noisy result plus the six non-color RR guides at `NodeFrameParameters::resolutionPlan.renderExtent`. The seven images are color `RGBA16F`, hardware depth `R32F`, diffuse albedo `RGBA16F`, specular albedo `RGBA16F`, world-space normal with linear roughness in alpha `RGBA16F`, jitter-decoupled previous-pixel-minus-current-pixel motion `RG16F`, and world-space specular hit distance `R16F`. Every image has one renderer-persistent slot per frame in flight with retained layout/access/ownership state and independent allocation extent/format metadata. Guide allocation is lazy during build and grows or reformats only the current frame slot after `Device::beginFrame()` has waited for that slot; other in-flight slots remain untouched. RDG declarations and ray dispatch use the current logical render extent even when the selected backing image is larger. The current `rtobject` schedule transfers them from the graphics PathTracing batch to the selected compute post-processing node. The node publishes the color as `frameResource::presentSourceColor` and all seven images as their explicit `dlss.rr.input.*` keys. It derives its link-time root variant from the immutable option snapshot, owns Slang assignment generation for `kMaxSurfaceBounces` and `RussianRoulettePolicy`, a node-local RT pipeline cache keyed by root variant, hit-group permutation set, and shader-session generation, and a separate SBT cache keyed by pipeline key plus hit record plan. Pipeline misses synchronously compile only Slang variants required by the active scene and create the RT PSO on the graph build thread; SBT misses rebuild only the shader-binding table for the active record plan. Its shader is split into a thin fixed `shader/renderer/pathTracing.slang` entry module plus focused `shader/renderer/pathTracing/*` modules: the entry constructs a `Scheduler`, the scheduler runs exactly one raygen path per pixel, `Pt` owns the per-path `PathState` plus trace/hit/miss/output methods, closest-hit builds a `ClosestHitInput` and delegates material payload resolution plus BSDF scatter sampling through the link-time `CHS : ICHS` contract in `shader/include/pathTracing/chs.slang`, and the raygen core performs pixel- and monotonic-sample-frame-based RNG seeding, direct lighting from glTF photometric scene lights, finite-distance shadow rays for punctual lights, emissive contribution, roulette, next-bounce state updates, and guide capture. The node splits hit selection into BSDF variant keys and a binary any-hit policy key: alpha-mask geometry and mixed-mesh single-sided geometry use `ahMaterialPolicy`, while ordinary opaque geometry keeps the hardware fast path and can reuse the same closest-hit CHS stage.
- PathTracing's default random sequence packs a Hilbert11 screen coordinate into 22 bits of the 32-bit Sobol index and keeps the remaining 10 bits for the in-era frame ordinal. The resulting 2048x2048 spatial period replaces the previous Hilbert8 256x256 period without adding per-path RNG state; higher frame-ordinal bits continue through the frame-shared era scramble seed.
- PathTracing keeps diffuse reflection, dielectric/metal reflection, and transmission behind one shared base-surface evaluate/PDF/sample entry. The existing layer-mask specialization still links base-only `1/3/5/7` and transmission-enabled `9/11/13/15` CHS programs separately, allowing inactive transmission code to be pruned. Thin folded-GGX leaves medium state unchanged; volume rough-dielectric transmission uses raw front/back faces, Snell/TIR, and a bounded strict-LIFO IOR stack keyed by dense instance metadata plus geometry index, with eta-aware roulette. IOR zero is preserved as the positive-infinity/Fresnel-one compatibility sentinel. Nested boundaries must be separate BLAS geometries; no path state stores internal distance, Beer absorption, or volume scattering.
- PathTracing resolves its scene dependencies as one private typed input bundle. Missing TLAS, incomplete RT sideband, and invalid SBT plan states share reason-labeled clears across the complete seven-image set. Its named RHI RT program assembly creates the stage/group mapping once; SBT sections and records query the resulting pipeline group names rather than assuming numeric group positions. It does not generate the optional experimental ray-direction, 3D-motion-vector, high-resolution-depth, disocclusion, or responsivity guides.
- PathTracing consumes the renderer-global scaled RGBA16F latitude-longitude environment through a dedicated reflected combined sampler and push constants. It samples only material-ray misses and the primary alpha-blend background; visibility rays, scene-light alias construction, direct-light sampling, and NEE do not consume the environment. Environment binding happens after the typed scene-input check, so missing TLAS/sideband keeps the existing clear behavior.
- Accumulate Node is the selectable non-RR `rtobject` post-processing mode. It independently snapshots the unjittered render-camera view/projection matrices, owns its sample count, and invalidates its history when that transform changes, its retained history images are recreated, or the renderer publishes a final frame-wide temporal reset.
- DlssRayReconstruction Node consumes only explicit `dlss.rr.input.*` frame keys, preserves the complete bundled DLSS 310.7.0 RR create/evaluate contract for non-option programmatic configuration, evaluates through `nr.rhi:dlss`, and normally publishes `dlss.rr.output.color` plus optional `dlss.rr.output.alpha`. Enabled state, quality, DLAA-only bypass, motion-vector visualization, and reset-history are declared in the shared graph option catalog; every structural, resolution, and build path resolves those values from the same immutable frame snapshot. Presets are not options: the five-quality preset array remains an explicit `DlssRayReconstructionNodeInput` programmatic setting and defaults to the SDK-selected `Default` preset. The bypass/quality validators reject incompatible single-option mutations instead of correcting a second value. Reset-history is a frame effect that claims the exact NGX evaluation pass and succeeds only if its compiled submit batch is accepted. There is no node-local UI, draft, pending input, or one-shot reset flag. Other create/evaluate settings, create flags, optional-resource inclusion, and subrect controls remain available only through `DlssRayReconstructionNodeInput`. Bypass still runs NGX evaluation and preserves RR history, but publishes the PathTracing input color to the configured output key instead of the RR output. The optional debug view runs after NGX so RR history continues normally, then replaces only the presented RR color with a logarithmically amplified visualization of the exact pixel-space MV input: neutral motion is `(R,G)=(0.5,0.5)`, R encodes X, G encodes Y, and invalid values are magenta. The default `rtobject` RR graph owns a bounded five-quality resolution controller: before scene extraction and node build, its generic renderer resolver calls `dlssResolutionRequestFromSnapshot(...)`, queries or reuses exact NGX optimal settings for the current display extent, and contributes display/render extents plus a transition reset for renderer finalization. Graph preflight verifies that every option consumed by this resolver is declared. PathTracing produces at the final render extent; coordinated RR forbids node-local size overrides, validates only the controller-owned request and extents, targets the display extent, and reuses the cached optimal settings without a second query. Disabling RR returns the identity plan so low-resolution PathTracing output cannot bypass reconstruction into Present. Standalone RR nodes without the controller retain their existing programmatic overrides and late optimal-settings query. Both paths validate query success, non-zero optimal/min/max dimensions, ordered target-bounded ranges, and DLAA target equality before feature creation. Automatic RR matrices come from `NodeFrameParameters::renderCameraConstants`, which is the actual selected scene or override camera before projection jitter; jitter is supplied separately and scaled by render extent. RR evaluation reset combines the snapshot effect, renderer-final resolution-plan reset, and feature-lifecycle reset directly; camera jitter state does not carry temporal invalidation. NGX is isolated in the project-owned MSVC Release bridge; MSVC and clang++/libc++ hosts use the same validated C ABI and Release feature DLL.
- NormalBuffer Node targets graphics queue output, outputs world-space normals for any scene, binds the scene geometry atlas once per parallel record chunk, and samples normal maps through the renderer global `gSceneTextures[]` bindless table using the selected UV0/UV1 set, per-texture affine transform, and normal scale. It uses `RasterPassBuilder::recordParallel(...)` to record independent contiguous ranges of scene raster draws.
- Ui Node targets graphics queue UI composition, drains any remaining app-owned sections, appends CPU Performance followed by GPU Performance as the fixed UI tail, finalizes the UI frame, uploads GPU-only texture pixels through the RHI upload ring before graph import, keeps overlay texture reads in the render graph resource-intent path, and uses its local texture-table revision only as the content mutation source for the renderer-owned bindless table cache. Viewer controls and the queued Frame Status section are rendered before ordinary catalog groups by the app-side presenter. It has no node-specific mutation callbacks; fullscreen and all other actionable controls schedule mutations through OptionSystem. UI texture images attach retained image states after upload synchronization so later RDG imports update their final sampled layout/access through the common tracking path.
- Present Node targets the compute queue final output path. It consumes `frameResource::presentSourceColor`, optionally composites `frameResource::uiColor` when a UI node published one, converts to the selected SDR/HDR swapchain output encoding into a retained imported converted-color image, and copies a swapchain-ready image. When a `PresentReadbackTarget` is provided, it inserts `Present.CopyToReadback` after compute conversion. After all optional screenshot/readback work, `Present.AcquireSwapchainImage` splits the pre-acquire work from `Present.CopyToSwapchain`; only the final transfer copy batch binds the acquired swapchain image and waits on image-available at `eTransfer`. Present copy/readback/screenshot passes use renderer transfer ops so image aspects, readback barriers, and present destination use declarations stay centralized. Tone mapping and UI opacity come from the immutable frame option snapshot. A capture effect claims its exact image-to-readback pass; only successful submission arms the continuation that saves the EXR after the captured frame slot's fence has completed.
- RenderGraph Skeleton reuse provides patch-only hit paths for every built-in `rtobject` node. AccelerationStructureBuild performs per-frame AS planning before lookup and selects an exact no-instance, TLAS-only, or dirty-BLAS structural variant; its hit path patches current imports, sideband payloads, build inputs, and callbacks without graph declarations. The renderer still falls back to one clean cold build if any exact node variant cannot be patched, but AS cold materialization must consume the already prepared packet and fails fast when preflight was skipped; it never runs a node-local planning fallback.

## Binding Checklist

Shader-visible bindings in this module must be reflection-led through renderer-side pass builders. Nodes should use `PipelineRuntime`, `NodeBuildContext::globalResources`, `RasterPassBuilder`, `ComputePassBuilder`, and `RayTracingPassBuilder` for persistent pipeline descriptor sets, renderer-owned global frame resources, static descriptor writes, push constants, dynamic descriptor snapshots, acceleration-structure descriptors, pass shader-stage scopes, and the split prepare/record deployment path. Raster passes should use explicit resource stage intent for known vertex-only or fragment-only descriptor access.

- Allowed direct command recording inside builder record callbacks: vertex/index buffers, draw/dispatch/trace, scissor overrides, per-draw dynamic state, barriers, and copy helpers.
- Direct `context.addPass(...)` remains appropriate for non-shader-visible AS-build/upload passes that do not update or bind shader descriptors. Built-in transfer clears and copies should prefer `nr::renderer::ops`; CPU uploads into GPU-only resources should use the RHI upload ring instead of node-local staging passes.
- Persistent imported buffers, images, and acceleration-structure backing storage can attach their type-safe retained state. The common state carries initialization, ownership, access, and last-submission timeline; `RetainedImageState` additionally carries layout. PathTracing's seven RR inputs retain one image set per frame in flight, preserving frame-slot lifetime isolation. Frame-local imports can remain untracked when frame-slot fences provide their full lifetime boundary, and graph-transient resources do not need retained state because RDG owns their lifetime for the frame.
- Per-node/pass/draw scalar payloads must use push constants only when they are no larger than `nr::rhi::kMaxPushConstantBytes` (128 bytes). Larger payloads must be split into renderer global frame uniforms or buffer/texture upload resources.
- Dynamic or bindless resources may provide a builder `dynamicBindingSnapshot(...)` callback using reflection cursors, but descriptor writes and command-buffer descriptor binding still stay inside the builder prepare/record path. Per-frame bindless descriptor table application caches are renderer-owned; render-pass nodes should not keep node-local applied-version caches.
- Scene bridge data that is consumed during deferred prepare/record work should be captured as `GraphFrameDataHandle` values from `NodeFrameParameters` and resolved through the pass context. Do not capture borrowed `SceneBridgeFrame` references or copy per-node bridge snapshots into record lambdas.
- Actionable node settings must be declared through `NodeRuntime::declareOptions(...)` and read from the same immutable `NodeFrameParameters::optionSnapshot` used by resolution planning and graph construction. Render-pass nodes must not expose node-local UI mutation callbacks or retain draft/pending option state. `UiNode` renders app-owned controls and diagnostics without owning option values.
- Scene/model raster passes that emit conventional clip-space Y-up positions should select `RasterViewportYMode::ClipSpaceYUp`; screen-space UI passes should keep the default framebuffer-top-left viewport mode.
- A pass that opts into `recordParallel(...)` must treat chunk replay order as semantically unordered. If a feature needs ordered draw groups, split it into multiple ordered passes and declare resource uses at those pass boundaries; use `nr::renderer::use::orderedAfterPrevious(...)` when the next pass needs an explicit barrier despite unchanged queue/layout.
- `NormalBuffer.Raster` consumes `SceneBridgeFrame::geometryBuffers` as the scene vertex/index atlas binding source. Each parallel chunk binds the atlas vertex buffer once, binds the atlas index buffer once when the frame has indexed geometry, and the per-draw loop changes only dynamic raster state, push constants, and atlas-adjusted draw parameters.
- Scene material texture IDs are 16-bit draw/RT metadata and default to 0. `NormalBuffer.Raster` pushes only its normal-slot sampling record; RT materials keep one dense texture reference per `MaterialTextureSlot`, including UV0/UV1 selection and a row-major 2x2 affine transform plus offset. Shader code should use `shader/include/share/materialTextureIds.slang` for the common slot order. Scene-texture-consuming PSOs install a linear immutable sampler for `gSceneTextures[]` before pipeline creation; renderer global resources bind `gSceneTextures[0]` to a 1x1 neutral white fallback (linear RGBA(1,1,1,1)) and bind resident scene texture image views at `TextureHandle.slot + 1` through a single set 1 / binding 0 variable descriptor array. Missing/unauthored RT material texture slots resolve to ID 0, so the neutral white default multiplies through factor-only material terms without a texture-presence branch. Before graph build, renderer collects table entries from both raster bridge materials and TLAS/RT material references, so PathTracing can sample materials that are only visible through the AS path. Passes that use or may use this table should call `nr.renderPasses:sceneTextureTableBinding`, which is a thin adapter into `RendererCacheSuite::bindlessImageTableCache`; descriptor-set allocation invalidation, fallback prefill, version checks, resident-slot updates, and removed-slot fallback rewrites are renderer-owned.
- `AccelerationStructureBuildNode` consumes build-time scene TLAS packets and scene AS mesh queries only during node build. Its revision-keyed structural plan owns immutable metadata, material tables, ordered instance templates, unique mesh semantics, and a shared read-only SBT plan; old graph frames retain that SBT plan safely after cache replacement. It keeps BLAS storage in a node-owned atlas buffer, invalidates cached descriptors and rebuilds BLAS on mesh content/layout revisions, repacks/rebuilds on real atlas growth without growing capacity for revision-only replacement, and validates TLAS hit SBT bucket offsets against the configured hit record count. Its deferred record callbacks resolve node-private graph frame data and call `nr.rhi` AS helpers; they must not capture borrowed scene references.
- `AccelerationStructureBuildNode` compiles the RT-only multilayer material table on structural misses. Material and texture binding/payload/residency revisions are authoritative material-cache invalidators; texture content is excluded because the compiled table stores descriptor IDs rather than image payload. Static instance/geometry/material sideband buffers are written once per frame slot and structural-plan generation, while dynamic transform, mask, BLAS address, instance-buffer writes, and TLAS build remain per-frame; RT facing stays the mesh's object-space winding policy. It publishes the scene geometry atlas buffers so RT shader-visible nodes can bind all sideband resources through `RayTracingPassBuilder`.
- `LightPrepareNode` keeps one CPU-visible header buffer, one CPU-visible record buffer, and one CPU-visible alias-table buffer per frame slot. Alias weights are Rec.709 luminance times glTF photometric intensity. It inserts a default warm directional sun before scene-authored lights, so normal PathTracing frames have at least one positive-energy alias-table entry; the lower-level alias builder still supports zero-count dummy tables for direct helper use.
- Not allowed in nodes: hand-written descriptor-set update/bind flows, direct `ShaderBindingPool::update(...)` or `resolveDescriptorWriteRequests(...)` usage, direct `CursorPipelineLayout::bindDescriptorSets(...)` for shader-visible bindings, direct `updateResourcesForBindingSnapshot(...)`, direct `bindPreparedResourcesToCommandBuffer(...)`, or direct `pushConstantsToCommandBuffer(...)`.

Current binding status: all built-in project-shader passes use `RasterPassBuilder`, `ComputePassBuilder`, or `RayTracingPassBuilder`. `NormalBuffer.Raster` is the built-in unordered parallel raster pass. Built-in transfer clears/copies, including PathTracing fallback clears and Present readback/screenshot/swapchain copies, use `nr::renderer::ops`. `AccelerationStructureBuildNode` and `LightPrepare.Upload` use direct `context.addPass(...)` because they are AS-build/upload graph passes without shader-visible bindings; `DlssRayReconstructionNode` uses it to record the typed external NGX evaluation after declaring every image use to RDG.
