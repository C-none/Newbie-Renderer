# RenderPasses Module Terminology

This module uses the same fixed terms as renderer:

- Node: top-level feature unit.
- pass: executable unit emitted by a Node.
- submitNode: debug-named graph control marker (not a business Node).

Rules:

- A Node may emit multiple passes.
- EmbeddedTriangle Node targets graphics queue output, binds renderer global frame uniforms, and emits a single draw-call demo pass.
- AccelerationStructureBuild Node targets graphics or compute queue AS build work, owns renderer-side BLAS/TLAS cache resources plus RT material sideband frame buffers, allocates BLAS storage from one node-owned atlas buffer, batches dirty rebuild-only BLAS builds, rebuilds TLAS from scene TLAS packets, and publishes `frameResource::sceneTlas` with dense instance/geometry/material metadata plus scene vertex/index atlas resources for RT shaders.
- LightPrepare Node targets CPU-to-GPU frame upload work, prepends the warm default directional sun light, consumes active scene light packets, writes the set 6 scene light header/list/alias-table buffers into per-frame CPU-visible GPU buffers, and publishes `frameResource::sceneLightHeader`, `frameResource::sceneLights`, plus `frameResource::sceneLightAliasTable`.
- PathTracing Node targets ray tracing work, consumes `frameResource::sceneTlas`, the RT material sideband buffers, scene vertex/index atlas resources, published scene light buffers, and `frameData::sceneRtHitSbtPlan`, and publishes `frameResource::presentSourceColor` as a fixed 1spp single-frame result. It registers compile-affecting `maxSurfaceBounces` and `enableRussianRoulette` variant items; generated variant UI patches are committed by the renderer next frame, and runtime misses synchronously compile the Slang variant and create the RT PSO/SBT on the graph build thread. Its shader is split into a thin fixed `shader/renderer/pathTracing.slang` entry module plus focused `shader/renderer/pathTracing/*` modules: the entry constructs a `Scheduler`, the scheduler runs exactly one raygen path per pixel, `Pt` owns the per-path `PathState` plus trace/hit/miss/output methods, closest-hit builds a `PathTracingClosestHitInput` and delegates material payload resolution through the link-time `CHS : ICHS` contract in `shader/include/pathTracing/chs.slang`, and the raygen core performs pixel- and monotonic-sample-frame-based RNG seeding, direct lighting from glTF photometric scene lights, finite-distance shadow rays for punctual lights, emissive contribution, and v1 diffuse/GGX scatter recursion. The node compiles the global path-tracing variant once per runtime key and links one lightweight CHS type alias component per unique hit permutation while preserving per-geometry SBT records.
- Accumulate Node targets compute-queue history accumulation for the path tracing pipeline. It consumes the single-frame `frameResource::presentSourceColor`, reads the previous accumulated history image, writes the next history image, republishes `frameResource::presentSourceColor`, resets when renderer camera stability state changes, and clamps the current-frame EMA weight after the configured stable sample cap. Its two renderer-persistent history slots attach retained image states so RDG imports start from the previous frame's final layout/access. Its history-sample input defaults to 1024, clamps to `[1,4096]`, and is registered as a runtime-only variant item so UI changes do not trigger PSO rebuilds.
- NormalBuffer Node targets graphics queue output, outputs world-space normals for any scene, binds the scene geometry atlas once per parallel record chunk, samples normal maps through the renderer global `gSceneTextures[]` bindless table when a draw provides a non-zero normal texture ID, and uses `RasterPassBuilder::recordParallel(...)` to record independent contiguous ranges of scene raster draws.
- Ui Node targets graphics queue UI composition, renders app sections plus renderer-collected node UI sections, uploads GPU-only texture pixels through the RHI upload ring before graph import, keeps overlay texture reads in the render graph resource-intent path, and uses its local texture-table revision only as the content mutation source for the renderer-owned bindless table cache. UI texture images attach retained image states after upload synchronization so later RDG imports update their final sampled layout/access through the common tracking path.
- Present Node targets the compute queue final output path. It consumes `frameResource::presentSourceColor`, optionally composites `frameResource::uiColor` when a UI node published one, converts to the selected SDR/HDR swapchain output encoding into a retained imported converted-color image, and copies a swapchain-ready image. When a `PresentReadbackTarget` is provided, it inserts `Present.CopyToReadback` after compute conversion and before `Present.CopyToSwapchain`, copying the converted SDR/HDR output image into a host-visible transfer-dst buffer on the same compute queue. Its UI panel stages next-frame opacity changes and screenshot requests; screenshots copy the pre-present linear source image directly into a node-owned readback buffer and save an EXR after the captured frame slot's fence has completed.

## Binding Checklist

Shader-visible bindings in this module must be reflection-led through renderer-side pass builders. Nodes should use `PipelineRuntime`, `NodeBuildContext::globalResources`, `RasterPassBuilder`, `ComputePassBuilder`, and `RayTracingPassBuilder` for persistent pipeline descriptor sets, renderer-owned global frame resources, static descriptor writes, push constants, dynamic descriptor snapshots, acceleration-structure descriptors, pass shader-stage scopes, and the split prepare/record deployment path. Raster passes should use explicit resource stage intent for known vertex-only or fragment-only descriptor access.

- Allowed direct command recording inside builder record callbacks: vertex/index buffers, draw/dispatch/trace, scissor overrides, per-draw dynamic state, barriers, and copy helpers.
- Direct `context.addPass(...)` remains appropriate for non-shader-visible transfer/copy/AS-build/upload passes that do not update or bind shader descriptors. CPU uploads into GPU-only resources should use the RHI upload ring instead of node-local staging passes.
- Renderer-persistent imported images that can be reused across frames must attach `nr::renderer::RetainedImageState` through the imported-image descriptor or a retained import helper. Frame-local imported images, such as `NormalBuffer.Color` / `NormalBuffer.Depth`, `Ui.Buffer`, and per-frame UI buffers, can continue to start from `Undefined` because frame-slot fences prevent overlap. Graph-transient images, such as `PathTracing.Output` and embedded triangle output, do not need retained state because RDG owns their lifetime for the frame. Scene bindless textures that are not graph-imported images remain governed by the existing upload/retirement lifetime rules; this contract does not extend retained tracking to buffers or acceleration structures.
- Per-node/pass/draw scalar payloads must use push constants only when they are no larger than `nr::rhi::kMaxPushConstantBytes` (128 bytes). Larger payloads must be split into renderer global frame uniforms or buffer/texture upload resources.
- Dynamic or bindless resources may provide a builder `dynamicBindingSnapshot(...)` callback using reflection cursors, but descriptor writes and command-buffer descriptor binding still stay inside the builder prepare/record path. Per-frame bindless descriptor table application caches are renderer-owned; render-pass nodes should not keep node-local applied-version caches.
- Scene bridge data that is consumed during deferred prepare/record work should be captured as `GraphFrameDataHandle` values from `NodeFrameParameters` and resolved through the pass context. Do not capture borrowed `SceneBridgeFrame` references or copy per-node bridge snapshots into record lambdas.
- Optional command-style node UI belongs in `NodeRuntime::collectUi(...)`. Compile-affecting and runtime-only settings should prefer renderer variant registry items so generated UI can submit next-frame patches consistently. `UiNode` displays the collected and generated sections but does not own their state.
- Scene/model raster passes that emit conventional clip-space Y-up positions should select `RasterViewportYMode::ClipSpaceYUp`; screen-space UI passes should keep the default framebuffer-top-left viewport mode.
- A pass that opts into `recordParallel(...)` must treat chunk replay order as semantically unordered. If a feature needs ordered draw groups, split it into multiple ordered passes and declare resource uses at those pass boundaries; use `nr::renderer::use::orderedAfterPrevious(...)` when the next pass needs an explicit barrier despite unchanged queue/layout.
- `NormalBuffer.Raster` consumes `SceneBridgeFrame::geometryBuffers` as the scene vertex/index atlas binding source. Each parallel chunk binds the atlas vertex buffer once, binds the atlas index buffer once when the frame has indexed geometry, and the per-draw loop changes only dynamic raster state, push constants, and atlas-adjusted draw parameters.
- Scene material texture IDs in raster push constants default to 0 and are packed as two 16-bit IDs per 32-bit lane. RT material texture references use the same descriptor IDs. Shader code should use `shader/include/share/materialTextureIds.slang` for `MaterialTextureSlot` and flags, and `shader/include/materialTextureIds.slang` for unpacking helpers. Scene-texture-consuming PSOs install a linear immutable sampler for `gSceneTextures[]` before pipeline creation; renderer global resources bind `gSceneTextures[0]` to a 1x1 purple fallback and bind resident scene texture image views at `TextureHandle.slot + 1` through a single set 1 / binding 0 variable descriptor array. Before graph build, renderer collects table entries from both raster bridge materials and TLAS/RT material references, so PathTracing can sample materials that are only visible through the AS path. Passes that use or may use this table should call `nr.renderPasses:sceneTextureTableBinding`, which is a thin adapter into `RendererCacheSuite::bindlessImageTableCache`; descriptor-set allocation invalidation, fallback prefill, version checks, resident-slot updates, and removed-slot fallback rewrites are renderer-owned.
- `AccelerationStructureBuildNode` consumes build-time scene TLAS packets and scene AS mesh queries only during node build. It keeps BLAS storage in a node-owned atlas buffer, repacks/rebuilds on atlas growth instead of copying opaque AS storage, and validates TLAS hit SBT bucket offsets against the configured hit record count. Its deferred record callbacks resolve node-private graph frame data and call `nr.rhi` AS helpers; they must not capture borrowed scene references.
- `AccelerationStructureBuildNode` also compiles the frame's RT-only multilayer material table from resident scene materials during node build. It writes instance metadata, geometry-to-material and primitive-address records, material headers, ordered layer records, and material texture references into imported storage buffers, then publishes the scene geometry atlas buffers so RT shader-visible nodes can bind all of them through `RayTracingPassBuilder`.
- `LightPrepareNode` keeps one CPU-visible header buffer, one CPU-visible record buffer, and one CPU-visible alias-table buffer per frame slot. Alias weights are Rec.709 luminance times glTF photometric intensity. It inserts a default warm directional sun before scene-authored lights, so normal PathTracing frames have at least one positive-energy alias-table entry; the lower-level alias builder still supports zero-count dummy tables for direct helper use.
- Not allowed in nodes: hand-written descriptor-set update/bind flows, direct `ShaderBindingPool::update(...)` or `resolveDescriptorWriteRequests(...)` usage, direct `CursorPipelineLayout::bindDescriptorSets(...)` for shader-visible bindings, direct `updateResourcesForBindingSnapshot(...)`, direct `bindPreparedResourcesToCommandBuffer(...)`, or direct `pushConstantsToCommandBuffer(...)`.

Current audit note: all built-in shader-visible passes use `RasterPassBuilder`, `ComputePassBuilder`, or `RayTracingPassBuilder`. `NormalBuffer.Raster` is the built-in unordered parallel raster pass. `AccelerationStructureBuildNode`, `LightPrepare.Upload`, `Present.CopyToReadback`, `Present.CopyScreenshotToReadback`, and `Present.CopyToSwapchain` still use direct `context.addPass(...)` because they are AS-build/upload/copy graph passes without shader-visible bindings.
