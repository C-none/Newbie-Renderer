# Renderer Module Terminology

This module uses the following fixed terms:

- Node: a feature-level graph producer that can emit one or more passes.
- pass: an executable graph unit with queue domain, shader stage scope, resource and frame-data capability declarations, and either a serial record callback, an unordered parallel range-record contract, or an implicit copy path.
- prepare: main-thread pass stage for runtime resource resolution, CPU buffer writes, descriptor updates, upload staging setup, and other per-frame mutable preparation.
- record: worker-capable pass stage for command-buffer recording only.
- submitNode: a debug-named execution-control marker that splits submit batches; a swapchain-acquire submitNode additionally delays WSI acquire until its opened batch is about to record and submit.

Scope boundary:

- renderer owns frame-graph build/compile/execute orchestration, renderer-persistent resources, graph-transient planning, queue submit structure, and present orchestration.
- renderer does not own scene asset lifecycle or input handling.
- `RendererGraphSpec::frameResolutionResolver` is the optional generic per-frame resolution policy boundary. For a non-empty resolver, renderer uses the frame input timeout to acquire immediately after `Device::beginFrame()`, then snapshots the post-acquire display state and resolves a `FrameResolutionPlan` contribution. Renderer validates its extents, merges renderer-global temporal invalidations into `resetHistory`, and publishes that final plan once through `NodeFrameParameters`; controller snapshots retain only controller-owned request, extent, and settings data. `Renderer::requestTemporalHistoryReset()` is the narrow external arm for a successfully committed reset-marked option, including every PathTracing integrator-policy transition. It affects the next final resolution plan but deliberately does not restart the monotonic sample-frame ordinal. The executor reuses the active image at the compiled acquire boundary without acquiring twice; graphs without a resolver retain the late-acquire path and use an identity plan. Scene extraction and default camera aspect remain display-sized, while camera jitter pixel-to-NDC conversion uses the render extent and `RendererCameraFrameState` remains limited to jitter state.
- present path is compute-queue oriented.
- RDG execution is three-stage: build/compile/prepare on the main thread, pass command recording on the shared `nr.utils:threading` static worker pool into secondary command buffers, then per-batch compiled-order secondary merge, submit, and present on the main thread. Recording is launched batch-by-batch so ordinary graphs can submit pre-acquire batches before a late swapchain-acquire boundary blocks the CPU. Resolver graphs intentionally pre-acquire before build so resolution-dependent work observes the final presentation extent, while image binding, image-available waiting, final submit, and present remain at the compiled boundary.
- The main thread is an aggregation and submit owner during execute. Worker pass recording must use worker-only secondary pool slots; slot 0 is reserved away from RDG pass record tasks.
- Submit batch GPU debug labels include the submitNode debug name when the batch was opened by an explicit submit marker.
- Renderer owns one submission timeline semaphore and monotonic signal-value sequence per queue domain. Submit tokens carry both the producer queue and its timeline value, so an adjacent consumer waits on the semaphore belonging to the queue that produced the token. Adjacent submit batches derive their timeline wait stage from the union of the boundary's actual first consumer scopes instead of using a queue-wide all-commands mask. Before emitting a queue-family ownership transfer, executor preparation applies the device `QueueFamilyTransferPolicy` to buffers, acceleration-structure storage buffers, and images. Same-family, concurrent-sharing, and maintenance9-eligible transitions omit the QFOT while preserving timeline ordering and any required consumer-side image layout transition. Remaining cross-family transitions use split release/acquire barriers with maintenance8 all-stage dependency semantics; release barriers use the producer stage on both sides and acquire barriers use the consumer stage on both sides. Swapchain resources are late-bound after the explicit acquire control boundary, and the image-available wait is placed at that final batch's first compiled swapchain-image access.
- `RenderGraphBuilder` validates and canonicalizes every pass capability before storage. Resource-use duplicates collapse in first-declaration order, conflicting declarations for one handle fail fast, and only an implicit image-copy destination followed by its terminal present read may retain two entries. Frame-data handles must be valid and belong to the current frame; duplicates are removed stably. Compiler synchronization uses the precise declared resource scopes: same-queue/same-batch RAW, WAR, WAW, layout changes, and explicit ordering markers produce barriers, while unmarked RAR does not. Initialized retained first uses participate in the same hazard analysis even when layout and ownership stay fixed; unresolved retained source scopes are conservative, whereas uninitialized resources do not acquire a fabricated predecessor.
- When `VK_EXT_frame_boundary` is enabled by a capture tool, RDG submit batches for one frame share a monotonic frame-boundary ID and the final compute-present submit is marked as the frame end.
- Env-driven Nsight Graphics capture/trace control is owned by the RHI `NsightGraphicsFrameHelper` and invoked from `nr.rhi::Device`; renderer frame orchestration keeps the same begin/build/execute/present flow.
- `RendererCacheSuite` is the renderer/RDG derived-state cache boundary. It owns the bounded exact-variant `RenderGraphSkeletonCache`, `RenderGraphCompileCache`, `BindlessImageTableCache`, and `RendererGlobalDescriptorTableCache`; it does not own scene content lifetime, UI texture lifetime, node-owned GPU resources, pipelines, AS storage, shader variant state, or material content caches. Skeleton entries contain normalized CPU structure only. Every built-in `rtobject` node supports exact patch-only reuse, including preflight-planned no-instance, TLAS-only, and dirty-BLAS AccelerationStructureBuild variants.
- `RenderGraphCompileCache` caches compiled graph templates by resource/pass/submit structure, including each pass's frame-data capability vector, and patches current frame data, callbacks, imported buffer/image/AS refs, retained external-state refs, and debug names on a hit. Its resource-use signature directly reuses the canonical `PassResourceUseDesc`, so typed usage/access, layout/aspect, shader scope, ownership override, and explicit previous-use ordering remain exact cache-key state without a mirrored projection. Debug names do not participate in the cache key; submit-boundary kind and retained initial layout/ownership/access state do participate. Swapchain image indices are not graph-build inputs because the executor binds the acquired image at runtime.
- Public `nr::renderer::use::*` resource-use construction is a named semantic API. The implementation uses local non-template constructors, while read/write behavior is derived solely from the typed buffer, image, or acceleration-structure access intent rather than a second boolean flag.
- `BindlessImageTableCache` owns applied descriptor table versions and active descriptor IDs per validated pipeline pass-binding owner, table, and frame slot. Scene texture tables and UI texture tables pass the builder-provided typed owner explicitly. A descriptor-set reallocation invalidates every cached table for that owner/frame, and `PipelineRuntime` merges variable descriptor counts by set so independently prepared tables do not erase one another or trigger allocation churn. Each owner-local `DescriptorWriteCache` still suppresses redundant Vulkan descriptor writes after a snapshot is produced.
- `RendererGlobalDescriptorTableCache` owns scene texture descriptor key/version calculation. Renderer assembles its scene-texture input from raster bridge material IDs plus TLAS/RT material references before graph build; TLAS-only collection may omit an unavailable authored anisotropy binding so shader-side semantic fallback remains reachable, while raster collection and every other material slot remain strict. Scene texture descriptor payloads carry image views/layouts because the shared nearest LOD0 sampler is immutable in consuming PSO layouts; the renderer-global environment retains a separate linear sampler, and scene/UI content caches continue to own texture allocation, residency, and mutation revision sources.
- `PipelineRuntime`, renderer-owned `FrameUniformArena`, `FrameGlobalResources`, `RasterPassBuilder`, `ComputePassBuilder`, and `RayTracingPassBuilder` are renderer-side helper abstractions for common node boilerplate. `PipelineRuntime<T>::PassBindingHandle` identifies one logical pass owner derived from the node runtime name plus node-local pass ordinal; cold materialization and Skeleton patching therefore reuse the same owner, while different passes and frame slots keep separate descriptor sets, variable-count maps, and descriptor-write caches. Runtime reset/reinitialization clears those states and advances a generation so stale or foreign handles fail fast. Every descriptor-state API requires the typed handle. Prepare callbacks first finalize owner-local variable counts and any resulting reallocation, then apply the static snapshot followed by dynamic snapshots; record callbacks bind only that owner's prepared sets, including all chunks of one parallel raster pass. The helpers also provide renderer-owned global CPU-to-GPU frame uniform upload, 128-byte-limited push constants, explicit `.frameData(...)` capability declaration, and shader-visible prepare/record glue. Builders stamp pass shader scopes independently of queue domain (`eAllGraphics`, `eComputeShader`, or `eRayTracingShaderKHR`), and shader resource-use descriptors can narrow raster resources further with explicit vertex/fragment stage intent.
- RDG resources model buffers, images, late-bound swapchain images, and imported acceleration structures. Imported images can opt into retained state tracking so renderer-persistent images feed the next frame's initial layout, ownership, access scope, and last-use queue timeline value from the previous submitted frame. Every normal graph batch signals its queue timeline as part of the existing submit. When a saved owner differs from the first-use queue, executor preparation first checks whether the runtime transfer policy permits implicit acquisition; an omittable transfer waits on that retained timeline value and keeps only a required layout transition at the first consumer. If no retained signal is available or policy still requires QFOT, the executor submits the existing source-queue synthetic release and records the matching acquire. Default prepare and record resolvers reject resource handles not declared by the current compiled pass before global lookup; a declared handle requested through the wrong resource-kind resolver remains empty. The default logical descriptor resolver inherits this pass scope, while an explicitly supplied non-RDG resolver remains independent.
- RDG frame data models CPU-side per-frame payloads that pass callbacks may need after graph build. `GraphFrameDataHandle` is graph-owned and type-checked through `PassPrepareContext::frameData<T>` / `PassRecordContext::frameData<T>`; every deferred consumer must also declare the handle on its pass through a pass builder's `.frameData(...)` or the final `addPass(...)` span. Renderer uses this path to expose the scene `SceneBridgeFrame` without per-node value captures, and the executor enforces the same declaration during prepare, serial record, parallel planning, and parallel range record.
- Renderer resolves the optional scene primary camera only while constructing `SceneRenderBridgeBuildInput`. Nodes receive the selected unjittered scene-or-override result through `NodeFrameParameters::renderCameraConstants`; no second scene-only camera reference is retained in the node interface.
- Renderer uploads a fixed 416-byte `Renderer.GlobalFrameUniforms` record. Its ordinary view/projection/view-projection/inverse fields describe the current jittered render camera, while `unjitteredViewProjection` describes that same frame before jitter and `previousViewProjection` comes from the last frame accepted after graph execution. The previously exported `previousView` matrix had no Shader caller and its 64-byte slot now carries the current unjittered view-projection without changing descriptor or buffer ABI.
- Renderer retains one optional accepted temporal frame state containing the unjittered camera constants and an optional complete `SceneRevisionSnapshot`. Missing history, graph replacement, resize, scene presence changes, and any scene revision change contribute `FrameResolutionPlan::resetHistory`; camera movement alone does not. The current state is published only after graph execution succeeds, so graph construction cannot advance history on a rejected frame.
- Actionable renderer-node settings are declared through `NodeRuntime::declareOptions(...)` during graph preflight and are read only from the immutable `NodeFrameParameters::optionSnapshot`. A definition may mark a retained mutation as `resetsTemporalHistory`; after and only after canonical commit succeeds, pipeline execution forwards that policy to `Renderer::requestTemporalHistoryReset()`. Renderer does not expose a node-specific UI callback or a second writable settings path. App-owned diagnostics remain ordinary read-only UI sections carried through `FrameServices`.
- Environment residency is renderer-global rather than scene-owned. `Renderer::setEnvironmentMap(...)` uploads one scaled RGBA16F latitude-longitude image through the device upload ring, retains its shader-read state across frames, and publishes only an RDG handle plus decode/intensity/yaw parameters through `FrameGlobalResources`. The resource survives scene replacement and installed-graph replacement; renderer initialization supplies a 1x1 legacy-miss-color fallback for non-viewer consumers.
